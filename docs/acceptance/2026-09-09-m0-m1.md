# OpenBoard M0/M1 acceptance evidence

## Evidence collected

- `npm run verify:core`: contract validator, TypeScript build, and the full Node suite pass. The exact count is recorded from the final verification command rather than maintained manually here.
- `OPENBOARD_PORT=3187 npm start`: daemon starts and `/api/scene` returns the discovered `examples/orders.csv` scene.
- Web smoke tests prove `/api/scene`, `/api/visual/:id`, local D3/Observable Plot asset delivery, spatial controls, and WebSocket mutation events.
- The M1 workflow test covers create → clone/filter → regional patch → arrange → annotate → checkpoint → goto → fork, including parent lineage.
- Persistence tests cover scene snapshots, JSONL operations, checkpoints/forks metadata, and restart-time undo.
- Real browser check with Playwright against a live runtime: one `v1` card changed from `Failure rate by channel` to `Daily failure-rate trend`; DOM reported `Revision 2`, one card, one navigation entry, and a rendered SVG. Console reported zero errors and zero warnings.
- Open Visual Grammar check: one `orders-by-channel` visual kept its id and query while patching `cartesian + barY` → `polar + primitive arc` → donut (`innerRadius`) → radial (`radius`); mixed Plot + primitive layers and a custom `path`/`circle`/`text` visual compiled successfully. The live browser showed the final radial SVG at Revision 4.
- LC2 retained-construction check: WorkSession drafts, real inspect/query/render activities, semantic patches, and one atomic `work.commit` revision are delivered over ordered WebSocket events. Work events name the affected visual IDs so the browser updates only changed cards; inspect/query-only activity does not re-render the canvas.
- LC2 strict entry check: every chart create, patch, and clone requires an explicit `work.apply({ action: "begin" })` and `work_id`; runtime, MCP schemas, HTTP validation, and contract JSON all reject the missing-work path. There is no implicit WorkSession compatibility route.
- LC2 boundary check: work overlays reject durable-ID collisions, immutable visual-field changes, duplicate annotations, and annotations targeting missing visuals. Raw SQL rejects mutating CTEs before DuckDB execution, and restored dataset paths are revalidated inside the configured data root.

## M1 status

Accepted. Two local formats are discoverable and inspectable; structured QuerySpec and guarded read-only SQL work; clone/compose/annotate/history operations are persisted; all frozen marks compile; explicit render limits return `render_limit_exceeded` with suggestions; and restart restores the scene plus navigable history.

### History navigation semantics

`history.apply` with `undo`, `redo`, or `goto` is navigation to an existing immutable snapshot, not a new Scene mutation: it restores the target snapshot's revision and does not append a duplicate history operation. `checkpoint` and `fork` are persisted history metadata operations. All ordinary Scene mutations, including a completed WorkSession, still increment revision exactly once and append one immutable history record.

## Open Visual Grammar correction

The original M0/M1 mark registry remains the compatibility Plot registry. The runtime now also exposes a small primitive registry and compiles both registries into one render payload. `coordinate` is independent from marks, `encoding` supports field/constant references for cartesian and polar channels, and ordered marks act as visual layers. Primitive path data is validated as pure SVG geometry; executable HTML/JavaScript is rejected. No chart-template enum or per-chart renderer was added.
